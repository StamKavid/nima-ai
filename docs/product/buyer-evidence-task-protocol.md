# First buyer-to-evidence task protocol

Status: prepared 2026-11-28, no participants, consent or observations recorded.
This follows the owner's instruction to make one product flow usable and observe
its value. It does not establish that a view is implemented or that users benefit.

## One task and observable outcome

For an explicitly selected saved buyer/cohort, identify the leading reported
supplier group(s), explain the exact publication denominator and joint overlap,
then open one contributing original record and state what remains unknown.
Use the existing U3 result; the interface must not calculate another metric.
When review/fitness prevents an approved insight, correct completion includes
recognising that limit rather than inventing a conclusion.

The proposed first interface has four stops: cohort/buyer selection, participation
and trust details, contributing records, original evidence. It must preserve
Greek text, all tied groups, exact shares, unknowns and capture scope. This is a
single-operator flow over approved stored data; no source query or account is
created by the study. Interface specification/approval precedes product code.

## Observation procedure

1. Recruit a consenting target researcher/analyst through the owner. Do not send
   invitations automatically. Use a pseudonym and keep consent/contact details
   private. Release acceptance still requires the contract's three analysts.
2. Freeze the cohort, request/cutoff, artifact hashes, metric status, exact task
   wording, browser/environment and allowed help. Record prior answer exposure
   and builder familiarity. Do not claim a blind or independent test when exposed.
3. Record a manual baseline using only the same originals and definition. Record
   elapsed time, wrong counts/denominators, missing evidence and assistance.
4. After the view is implemented and verified, give the same bounded task through
   it. Record completion time, mistakes, missing information, source navigation,
   aid supplied and whether the outcome was useful. Disclose learning/order bias;
   counterbalance tasks or use a matched unseen cohort when available.
5. Save actual notes, not simulated participant responses. The private blank task
   log has no measurements. Report failures and confusion; do not infer speedup
   from automated browser timings or from the builder's own completion.

## Acceptance and handoff

The first observation should establish whether a target user can explain the
result's scope and reach the supporting original, including a refused/limited
case. Any claimed time saving needs an actual baseline and the recorded bias.
Software proof (parity, browser, keyboard, empty/limited/error behavior) and user
proof remain distinct. Keep observations and source data private; a reviewed
repository summary may contain aggregate findings and limitations.

If the flow does not help, record why and revise it before adding insight families.
Do not contact users, publish a service, widen source budgets or promote metrics
as an implicit part of this protocol.
